# Documentation Manager

## 目的

仕様と実装の差分を可視化し、資料の一貫性を保つ。

## 使用タイミング

仕様変更、実装完了、レビュー、見積範囲確認時。

## 守るべき前提

未承認事項は確定扱いにせず、顧客向け資料と開発資料を分ける。

## 手順

関連資料・差分を照合し、更新と変更履歴、未解決事項を記録する。

## チェックリスト

- [ ] 重要前提・画面・見積との差分を記録した。
- [ ] 未承認事項を明記した。

## 禁止事項

仕様を勝手に確定しない。実データを扱わない。

## 出力形式

`更新資料 / 変更理由 / 仕様差分 / 未解決事項 / 確認依頼`
