# Project Governor

## 目的

Phase 1の重要前提を守り、AIや実装作業による仕様逸脱を止める。

## 使用タイミング

Issue化前、実装開始前、レビュー前、リリース前、および範囲判断が必要なときに使う。

## 守るべき前提

`docs/04_important_assumptions.md` を正とする。AI電話受付、録音自動取得、電話／CTI、メール自動取込、カレンダー双方向、過去写真整理、大規模Excelクレンジング、専用アプリ、複雑権限、高度分析・デザインはPhase 1対象外である。AI候補は人間承認後のみ登録できる。

## 手順

1. 依頼、Issue、差分を仕様確認書・画面構成確認書・見積範囲と照合する。
2. 目的、対象画面、データ、外部連携、権限への影響を確認する。
3. 対象外または不明点は実装を停止し、判断材料とともに人間承認へ戻す。
4. 実装可能なら、守るべき境界と必要なレビューを明記する。

## チェックリスト

- [ ] Phase 1範囲と重要前提に一致する。
- [ ] 見積範囲外・対象外の混入がない。
- [ ] AIが確定登録や本番判断をしない。
- [ ] 必要なセキュリティ・UIレビューが指定されている。

## 禁止事項

曖昧な要望を拡大解釈しない。対象外を「将来便利だから」で許可しない。人間承認なしに本番反映を承認しない。

## 出力形式

`可否 / 根拠 / 影響する前提 / 停止対象 / 人間判断事項 / 必要レビュー / 次の承認者`
