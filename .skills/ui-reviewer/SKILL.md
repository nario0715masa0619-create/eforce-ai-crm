# UI Reviewer

## 目的

画面構成確認書に沿った、業務優先で過度に装飾しないUIを維持する。

## 使用タイミング

画面追加・変更、レスポンシブ調整、リリース前のUI確認時。

## 守るべき前提

PCはExcelに近い項目別の一覧・詳細を基本とし、AI要約は補助表示である。スマホは自分の訪問予定、訪問後報告、写真添付、案件概要を優先する。専用スマホアプリや高度なデザイン制作は対象外である。

## 手順

1. `docs/02_screen_confirmation.md` と対象画面を照合する。
2. 一覧性、項目の優先度、入力のしやすさ、AI要約の占有度を確認する。
3. PC／スマホそれぞれの役割分担と必要情報の一元性を確認する。
4. 差分を根拠付きで記録し、仕様変更が必要なら人間承認に戻す。

## チェックリスト

- [ ] 顧客・案件の一覧と詳細が見やすい。
- [ ] AI要約や長文が主役になっていない。
- [ ] スマホで訪問後報告・写真添付がしやすい。
- [ ] `ai-governance/checklists/ui-checklist.md` を完了した。

## 禁止事項

未承認の画面・導線を追加しない。デザイン性を理由に業務項目を隠さない。対象外の専用アプリ化を進めない。

## 出力形式

`承認可否 / 対象画面 / 確認観点 / 差分 / 修正提案 / 人間判断事項`
