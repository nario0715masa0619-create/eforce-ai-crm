# 仕様確認書（Issue #1 設計整理）

## 確定事項と対象外

- 電話問い合わせは録音音声を担当者がアップロードし、AIが文字起こし・抽出・要約・登録候補を作る。AI候補は担当者が確認・修正・承認してから登録する。
- メールは自動取込しない。必要な問い合わせだけを担当者が手動登録する。
- Googleカレンダーはシステムからの一方向登録だけを対象とし、Google側変更の自動反映、双方向連携、既存予定取込は対象外とする。
- 本文書は項目・関係性・表示仕様の整理であり、DB、画面、認証、AI、音声アップロード、ストレージ、カレンダー連携の実装は含まない。

## 顧客情報

| 項目 | 内容 |
| --- | --- |
| 顧客ID | 顧客を一意に識別するID |
| 氏名 / 電話番号 / 住所 / メールアドレス | 連絡・訪問に必要な基本情報 |
| 備考 | 担当者が記録する補足情報 |
| リピーター区分 | 初回・リピーター等の運用区分（候補） |
| 最終問い合わせ日 / 過去案件数 | 案件履歴から確認する一覧用の情報 |
| 作成日時 / 更新日時 / 作成者 / 更新者 | 入力・更新履歴の追跡情報 |
| 利用状態 | 利用中・停止等の運用状態（候補） |

### 重複候補判定

電話番号、氏名、住所を重複候補の確認項目とする。候補は表示のみとし、自動統合しない。統合・分離の最終判断は担当者が行う。

## 案件情報

案件は**問い合わせごと**に作成し、1案件は1顧客に紐づく。

| 項目 | 内容 |
| --- | --- |
| 案件ID / 顧客ID | 案件の一意な識別子と紐づく顧客 |
| 問い合わせ日時 / 問い合わせ経路 / 受付担当者 | 受付記録 |
| 買取希望品目 / 訪問希望日 | 問い合わせ内容・希望 |
| 訪問予定ID / 訪問担当者 | 訪問予定との参照・主担当 |
| 対応状況 / 見込み度 | 進行管理の区分（候補） |
| 備考 / AI要約 / 不足情報 | 補足、AIの補助表示、確認すべき不足項目 |
| 作成日時 / 更新日時 / 作成者 / 更新者 | 入力・更新履歴の追跡情報 |

問い合わせ経路の候補は、電話、メール、紹介、テレアポ、広告、その他とする。メールは自動取込しない。対応状況の候補は、未対応、受付済み、訪問予定、訪問済み、査定中、結果連絡済み、成約、不成立、キャンセルとする。

## 訪問予定

| 項目 | 内容 |
| --- | --- |
| 訪問予定ID / 案件ID / 顧客ID | 訪問予定の一意な識別子と紐づく案件・顧客 |
| 訪問日時 / 訪問先住所 / 地域 | 日程・訪問先情報 |
| 訪問担当者 / 複数担当者 | 主担当と複数担当者の設定 |
| 買取予定品目 / 備考 | 訪問の準備情報 |
| Googleカレンダー登録状況 / 登録日時 / イベントID | 一方向登録の状態を確認する情報 |
| 作成日時 / 更新日時 / 作成者 / 更新者 | 入力・更新履歴の追跡情報 |

Googleカレンダー連携は一方向登録のみとする。Google側変更の自動反映、双方向連携、既存予定の取込みは対象外である。

## 関係性

- 1人の顧客は複数の案件を持てる。1つの案件は1人の顧客に紐づく。
- 1つの案件は0件以上の訪問予定を持てる。1つの訪問予定は1つの案件に紐づく。
- 1つの訪問予定には1名または複数名の担当者を設定できる。
- 訪問後報告、写真、録音音声、AI抽出結果は案件に紐づける。

```text
顧客 (1) ──< 案件 (0..*) ──< 訪問予定 (0..*)
                  ├── 訪問後報告
                  ├── 写真
                  ├── 録音音声
                  └── AI抽出結果
訪問予定 (1) ── 担当者 (1..*)
```

## 画面・運用上の重要前提

画面はExcelに近い項目別の一覧・詳細を基本とし、AI要約は補助表示とする。スマホ専用アプリは作らない。顧客DB、写真、録音音声を外部公開せず、認証・基本権限・暗号化・アクセス制限・バックアップ・更新記録を前提とする。
