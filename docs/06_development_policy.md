# 開発方針

作業はIssueで範囲・対象外・完了条件を明確にした1タスク単位で行う。実装者、コードレビュー、セキュリティレビュー、UIレビュー、プロジェクト統制を分離し、仕様外や判断が曖昧な内容は実装せず確認事項に戻す。

本番反映、秘密情報変更、顧客データ投入、破壊的DB変更は人間の明示承認なしに行わない。

## Phase 0.5 開発環境整備

本体設計・本体実装に入る前に、開発環境を整備する。AI自律開発、クロスレビュー、夜間作業、旅行期間中のデバッグを安全に進めるため、開発環境・検証手順・ブランチ運用を先に整える。

### 整備対象

- 技術スタック、開発環境、ローカル起動手順、検証手順、CI
- ブランチ運用、PR運用、secrets管理、AI・夜間作業・本番反映ルール

### Phase 0.5でやらないこと

顧客・案件・訪問予定の詳細設計、DB設計、業務画面実装、AI処理実装、Googleカレンダー連携実装、本番環境構築は行わない。

## 検証・CI方針

CIはGitHub Actionsを利用する方針とし、最小アプリ雛形を作成する次工程でCI設定ファイルを作成する。CIでは lint、typecheck、test、build を必須確認とする。AIが作業した場合は、実行した検証コマンド、成功／失敗、失敗原因、未実行の場合の理由を報告する。テスト未実行のまま完了扱いにしない。

## Node.js / package manager方針

- Node.jsはLTS版を使用し、実装開始時点の具体バージョンは `.nvmrc` または同等の方法で明記する。
- package managerはpnpmを第一候補とし、lockfileをコミット対象とする。
- AIはpackage managerを勝手に変更せず、npm、yarn、pnpmを混在させない。

## secrets管理方針

- `.env` はコミットせず、`.env.example` のみをコミット対象とする。
- `.env.example` にはダミー値または説明だけを記載する。
- APIキー、認証情報、秘密情報をAIへ貼り付けず、GitHubにも置かない。
- 本番用秘密情報は人間が管理し、AIはAPIキーや秘密情報を変更しない。
- 顧客データ・実データをリポジトリに入れない。
- Supabase、Vercel、OpenAI、Google連携等の本番用秘密情報は人間が設定する。

## 環境分離方針

| 環境 | 用途 | データ・権限の方針 |
| --- | --- | --- |
| local | 開発者・AIによる検証 | 顧客・実データを使わず、ダミーデータのみを使う。 |
| staging | 本番前の操作確認 | 原則として実データを使わず、必要な場合も匿名化・最小化したデータに限定する。 |
| production | 本番運用 | 人間承認なしに反映せず、AIが直接変更しない。本番秘密情報は人間が管理する。 |

## ダミーデータ方針

開発・テストには顧客・実データを使わず、架空の氏名、電話番号、住所、メールアドレス、買取品目、訪問予定、録音音声メタ情報、写真メタ情報のみを使う。実在する顧客名、住所、電話番号、メールアドレス、録音音声、写真をリポジトリに入れない。

## ブランチ・PR運用方針

mainへの直接コミットは原則禁止とし、作業はIssue単位でブランチを切る。ブランチ名はIssue番号と作業内容が分かる名前にする。PRで少なくとも1名または1AIのレビューを必須とし、重要変更はClaude CodeとCodexの相互レビューを行う。CI通過後にマージし、本番反映は人間承認後のみとする。破壊的変更は事前承認を必要とする。

## GitHub保護設定方針

GitHub上で可能な範囲で、mainブランチ保護、Pull Request必須、CI通過必須、直接push制限、レビュー必須、force push禁止、branch削除制限を人間が確認・設定する。GitHub設定の変更は人間承認事項であり、AIが勝手に変更しない。

## Phase 0.6 Level 3オーケストレーション

本体設計・実装前にIssue／PR／docs／Actionsを中心とする半自動運用を整備する。ラベルと状態遷移で作業状態を管理し、`approved-for-work` なしにAIは作業せず、PRなしにレビューしない。ChatGPTはURL、commit、最小要約で判断し、チャット本文を正本にしない。詳細は `docs/13_ai_orchestration_level3.md` を参照する。
